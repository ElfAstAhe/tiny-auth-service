# ADR-005-SPEC: Спецификация аудита попыток аутентификации

## Статус
Принято (approved) - 15 Октябрь 2026 г.

## Контекст
В соотетствии с системной архитектурой нам необходимо жёстко фиксировать все попытки аутентификации пользователя в системе аудита

К строгой фиксации предьявляем следующие требования
1. **Фиксация попытки** при любом результате аутентификации
2. **Контроль гарантии доставки** только после этого удалять отправленные события

## Решение
Реализация через паттерн **outbox**. При успешной отправки события отмечаем запись как отправленную. Добавляем периодический worker удаления отправленных записей по истечению определённого периода.

1. Внутри базы данных `tiny-auth` реализовываем таблицу исходящих сообщений

```sql
create table if not exists login_attempts (
    id varchar(50) not null,
    data text not null,  -- можно как text или jsonb
    created_at timestamptz null default now(),
    --
    constraint login_attempts_pk primary key(id)
);
```

2. В микросервисе реализуем периодический worker мониторинга новых событий и отправка в целевой микросервис. Реализовать 4 маршрута:
* rest
* gRPC
* amqp
* kafka
3. Добавить в конфигурацию параметры настройки worker и клиентов
4. В микросервисе реализуем периодический worker мониторинга отправленных событий и удаления по истечению определённого периода.
5. Клиентов берём из библиотеки микросервиса `tiny-audit`
